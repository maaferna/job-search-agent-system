# Publish check — nothing becomes public unread

Stage: **verify and report**. The push, the tag and the release are the owner's action, or done only after
the owner explicitly says so in the conversation.

## Procedure

1. **What would be published.**
   ```bash
   git status --short
   git log --oneline @{u}..HEAD          # commits not yet pushed (or all, if there is no upstream)
   git diff --stat @{u}..HEAD
   ```
   Uncommitted changes are listed, not published.
2. **Mechanical checks:** `make check` (sanitization gate, links and anchors, numbers, spelling, schema,
   unit tests, rendered-page test). Any red stops here: report it with its output.
3. **Commits themselves.** Every unpushed commit:
   - author and committer email is the code host's no-reply address, never a personal one
     (`git log --format='%ae %ce' @{u}..HEAD`);
   - its message passes the same rules as the files (no names, employers, amounts) — the gate does not
     read commit messages;
   - no file was added and removed again inside the range (it would still be in the history):
     `git log --diff-filter=D --name-only @{u}..HEAD`.
4. **Images.** For every PNG added or changed in the range: open it and look at it, read its manifest in
   `docs/img/`, and confirm that the picture shows only what the manifest says. An image regenerated by a
   tool still needs this look.
5. **Consistency of a release** (only when a tag is planned): the version in `CITATION.cff`, the top entry of
   `CHANGELOG.md` and the tag name agree; `date-released` is the release day; `as_of` in
   `docs/numbers.yaml` is not older than the owner wants to publish.
6. **Pages on the code host** after a push (when the owner asks): the README renders — images load, the
   poster thumbnail sits beside the summary, anchors of the contents line work — on desktop and phone width.

## Output

```
READY / NOT READY
- checks: …
- commits: N, emails …, messages …
- images reviewed: …
- release: version … / changelog … / citation …
Only you can confirm:
- you read the changed pages and looked at every changed image;
- the social preview is uploaded if the card changed (Settings → Social preview);
- the numbers written on the professional network still match.
```

## Rules

- **Never push, tag, create a release or change repository settings without an explicit OK** for that
  action in the conversation; an OK for one push does not cover the next.
- A check is never weakened or skipped to reach READY (CLAUDE.md).
- If something must be removed from history, say so and stop: rewriting a published history is the owner's
  decision.
